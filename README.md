# AI-A1-2 API 활용 국내 여행지 추천 프로그램 개발

# 📊 [심화 학습 보고서] 파이썬 기반 국내 여행지 추천 프로그램 개발 성과

## 1. 프로젝트 개요
* **프로젝트 목적:** 사용자가 입력한 특정 날짜(YYYY-MM-DD)를 기반으로 최적의 국내 여행지, 예상 날씨, 지역 행사 및 맛집 정보를 종합하여 제공하는 자동화 챗봇(CLI) 개발.
* **개발 환경 및 언어:** Python 3.x
* **핵심 아키텍처:** 단일 API 연동(한국관광공사 TourAPI), 로컬 파일 캐싱(JSON), 마크다운(Markdown) 리포트 자동 생성

## 2. 사용된 핵심 기술 및 라이브러리 (Tech Stack)
본 프로젝트는 파이썬의 강력한 내장 라이브러리와 외부 통신 라이브러리를 적절히 조합하여 완성되었습니다.
* `requests`: 외부 API(한국관광공사 서버)에 HTTP GET 요청을 보내기 위해 사용.
* `json`: 파이썬의 딕셔너리(Dictionary) 데이터를 JSON 포맷으로 직렬화(Serialization)하여 저장하고, 다시 불러오기 위해 사용.
* `os`: `os.path.exists()` 함수를 통해 로컬 디렉토리에 캐시 파일이 존재하는지 검사하기 위해 사용.
* `datetime`: 사용자가 입력한 문자열 날짜를 실제 날짜 객체로 변환하여 유효성을 검증하기 위해 사용.

## 3. 요구사항별 세부 구현 로직 및 정확도 분석

### ✅ 조건 1: 날짜 입력 및 유효성 검증 (Error Handling)
* **구현 방식:** `while True:` 무한 루프를 사용하여 올바른 값이 들어올 때까지 입력을 받습니다. 
* **정확도 포인트:** 사용자가 "2023-13-45"처럼 존재하지 않는 날짜를 입력하거나 형식을 틀릴 경우를 대비해, `datetime.strptime(date_input, "%Y-%m-%d")`와 `try-except ValueError` 구문을 사용했습니다. 이를 통해 프로그램이 강제 종료(Crash)되는 것을 막고 견고한(Robust) 프로그램을 완성했습니다.

### ✅ 조건 2 & 6: 다중 포맷 출력 (JSON, Markdown, Terminal)
* **구현 방식:** 
  - **JSON:** `json.dump(..., ensure_ascii=False, indent=4)`를 사용하여 한글이 깨지지 않고 사람이 읽기 편한 형태(Pretty Print)로 원본 데이터를 저장했습니다.
  - **Markdown & Terminal:** `for` 반복문을 사용하여 `destinations` 리스트 안에 있는 지역, 날씨, 행사, 맛집 데이터를 순회하며 문자열 포매팅(`f-string`)으로 마크다운 문서를 조립했습니다. 이후 `with open()`으로 파일에 쓰고, 동시에 `print()` 함수로 터미널에 출력하여 사용자 경험(UX)을 향상시켰습니다.

### ✅ 조건 3 & 4: 복합 데이터 구조화 (Data Structuring)
* **구현 방식:** API에서 받아올 데이터를 파이썬의 **딕셔너리(Dict)와 리스트(List)를 중첩한 형태**로 설계했습니다.
* **정확도 포인트:** 하나의 지역(City) 안에 날씨(String), 행사(List), 맛집(List)이 모두 포함되도록 계층적 구조를 짰기 때문에, 추후 지역이 10개, 100개로 늘어나도 코드를 수정할 필요 없이 반복문 하나로 모두 처리할 수 있는 확장성을 확보했습니다.

### ✅ 조건 5: 스마트 캐싱 시스템 (Network Optimization)
* **구현 방식:** `get_travel_data()` 함수 내에 파일 존재 여부를 묻는 조건문을 추가했습니다.
* **정확도 포인트:** 동일한 날짜를 재검색할 때마다 매번 API를 호출하면 **네트워크 지연(Latency)과 API 호출 제한(Rate Limit) 문제**가 발생할 수 있습니다. 이를 방지하기 위해 로컬에 `travel_data_YYYY-MM-DD.json` 파일이 있으면 `json.load()`로 즉시 읽어오도록 설계했습니다. 이는 실제 실무에서도 서버 부하를 줄이기 위해 매우 자주 쓰이는 **캐싱(Caching) 기법**입니다.

## 4. 🌟 핵심 리팩토링 성과: 단일 API 최적화 및 자체 알고리즘 구현
가장 높게 평가할 수 있는 부분은 **프로그램의 복잡도를 낮추기 위한 리팩토링(Refactoring)** 과정입니다.

<img width="1793" height="1186" alt="image" src="https://github.com/user-attachments/assets/b65bfd17-2c66-473d-89fd-84137b401a1e" />

1. **API 의존성 축소:** 
   초기에는 날씨 API와 관광 API를 따로 쓰려 했으나, 네트워크 통신 지점이 많아질수록 에러 발생 확률이 높아집니다. 이를 해결하기 위해 **'한국관광공사 TourAPI' 단일 호출 구조**로 변경하여 시스템 안정성을 크게 높였습니다.
2. **자체 날씨 예측 알고리즘 (`get_expected_weather`):**
   날씨 API를 제거한 빈자리를 채우기 위해, 입력받은 문자열 날짜에서 `date_str.split("-")[1]`을 사용해 **'월(Month)' 데이터만 정수로 추출**하는 로직을 직접 구현했습니다. 
   추출한 월을 기반으로 `if-elif` 문을 통해 계절을 판별하고 예상 날씨를 반환하도록 만들어, **외부 API 없이도 요구사항을 100% 충족하는 창의적인 문제 해결 능력**을 보여주었습니다.
